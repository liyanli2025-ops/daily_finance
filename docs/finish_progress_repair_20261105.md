## 工程原因与改动

1. 旧拒绝签名包含事件索引、错误列表及待补任务；改写事件或切换错误会改变签名，绕过“同一次无进展”检查。新增 `discovery_action_plan.reject_finish` 仅依据真实候选 URL、合格正文及其已提供区间计进展。同一份资料连续两次无效 finish 就停止，不要求错误文字完全一样。新增候选或正文区间可重新获得修正机会；这是空转保护，不是整期模型轮数上限。
2. 新 `finish_repair` 明确要求下一步选工具，给出来源标题、原摘要、实际候选 ID、本地补读参数和搜索所需字段。核心范围缺口与本地补读优先于稿件修辞类任务。候选菜单有长度边界，省略整个条目而不裁改原文；完整目录和任务仍保留。程序不自动选第一条、不自动搜索。模型仍可说明逐项延期理由，但不得把缺口伪报为完成。
3. 原“可复用候选”只检查正文存在与一般准入，未检查目标用途，导致 MUFG 再次被推荐去补央行原披露、Kitco 晨报再次被推荐去补结算。现复用建议也核对用途、窗口和公司主体；背景稿可保留，但不再推荐去填其不符合的主资料缺口。政策采用自己的周末 168 小时窗口，不误套市场 96 小时窗口。
4. 原自动本地补读只在 tools 后执行，恢复后直接 finish 会一直跳过。现在进入控制器后，在下一次收费模型请求前先用原预算补读已存合格正文；不增加 HTTP、不改截止、不冒充模型已读，送达仍以完整模型响应的区间为准。
