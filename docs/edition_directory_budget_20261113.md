# v32：候选目录与阶段费用预留

范围限定为目录输入和预算核算。没有新增模型、搜索、补稿或收费验收轮次，没有修改服务商、模型、密钥、用户金额配置、自动化暂停或正文提取依赖。

## 候选目录

选题输入使用固定列顺序保留每条候选的标题、URL、完整摘要和原始时间；重复的检索范围、来源提示、用途及限制通过共享表引用。候选ID全部保留，独有风险和未知字段不删除。编码有明确说明；遇到保留标识冲突或编码没有变小，回退原始数据。

从历史92条目录实际做数据组装与复算，原候选对象JSON为85,120字符（含`candidates`外层），原紧凑JSON为81,900字符；新目录为46,807字符。新目录仍为92条，可以还原原候选字段。此为字符统计，不能当作token降幅、费用降幅或模型理解通过。

只去重仍不能保证“所有候选摘要+所有正文”放进65,000字符。评估阶段进一步按职责省去已存在正文、或已被选题单明确排除的候选摘要；保留其标题、URL、时间、范围、风险和选题单里的排除理由。摘要省略有明确说明，原摘要留在账本。**重大事件候选和未读且未排除的候选仍提供完整摘要。**已排除标题仍可被评估指出为遗漏并申请补查。

这与选题输入的无损编码是两件事：评估阶段是明确的字段选择，不宣称输入仍包含每条原摘要；程序不靠删候选来缩小输入。真实大范围若仍超出额度，停止并保留资料，不静默增加模型轮次或删除重大事件。

## 费用预留

不再将未来写稿/审稿统一按每次65,000字符乘4字节预留。新流程每次请求前，依据完整系统提示词、当前全部已保存正文、事件/证据检查以及旧报告计算已知输入字节；即使正文暂未入选也计入规划，避免乐观遗漏反方资料。

稿件尚未生成时，审稿单列“写稿输出额度×每token四字节”的待生成稿预留；稿件生成后改为实际保存的稿件。未知未来正文和评估结论可能增加输入，后续每次请求都重算；这不是提前保证一期一定能完成的预算。

实际请求继续按组装后的完整UTF-8字节数、配置输入/缓存最高价格和输出额度预留。**没有用较乐观token比例降低保护，没有取消最终请求的字符、累计输入、输出和调用次数边界。**正常仍4次模型请求，有新增正文才增加一次补查评估。

完整Anthropic/Ofox Anthropic成功回执同时提供非负整数的输入、输出、缓存读、缓存写token时，以回执用量乘已接受价格更新本期核算。原始估算、原回执、次数和累计输入/输出记录保留。缓存未知、失败、网络错误和口径不明确的兼容提供商继续占用完整原预留；回执核算高于原预留也如实增加，不裁成原估算。

`usage_priced_usd`是按已配置价格计算的用量金额，不是查询账户实际扣款。缓存写的具体TTL单价仍以配置为准，不能据此承诺服务商硬账单上限。回执、输入审计和未来写审规划进入可读账本。

用户尚未接受新价格或开启收费。约$0.50/期仍只是上一轮的设计情景，**本补丁没有把它写成运行配置，也没有证明当前真实一期可以在该金额内完成。**预算不足时保存缺口停止。
