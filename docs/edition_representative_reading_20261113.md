# v33：先选代表稿，再按具体缺口补读

## 已确认的问题与修改

v32目录/动态费用的43条服务器隔离测试已通过，但没有v32安装回执。服务器仍按已安装v31记录。此前初次选题允许同一事件读取多个来源；更严重的是补搜后把所有返回候选都加入下载。这里只缩小模型输入不能解决重复下载与重复正文费用。

本次改同一个生产入口，不另建收费试验runner：

1. 先批量搜索标题、摘要、链接与原时点。选题模型合并事件，指定一篇代表稿；若多选，只执行模型首选的一篇，其他候选记录为待读，不机械读取搜索第一条。
2. 代表稿正文合格时不自动下载同事件其他稿件。读不到/推广被排除时，在未尝试候选中按用途与缺口词匹配选一个替代，最多一次，不增加模型调用。
3. 证据评估可要求原披露、更新、独立核实、反证、背景或访问失败换源；每个请求必须记录类别与12—400字具体问题。同事件同类缺口最多读一篇，明确模型指定的来源优先。程序只校验结构，不能证明理由充分或事实正确。
4. 补搜结果保留在目录；按用途、声明上游/转载线索、标题摘要匹配选择一篇。同一缺口的多个查询一起筛选，不下载全部结果。已声明同一上游的转载不能作为独立核实来源；未知上游不认证独立性。同标题新时点仍可作更新线索。
5. 可读回执记录选择的标题、URL、具体补读原因、未读ID；原始目录不删除，未读不标记为已读。实际下载和来源准入沿用原预算、回执、正文质量及引用检查。

正常4次模型、确有新增正文才允许条件第5次；无新增正文不买第二次评估。不改金额、模型、搜索开关、凭据或生产暂停。历史失败、费用不重置。
