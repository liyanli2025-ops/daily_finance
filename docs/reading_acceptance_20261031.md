## 解决的问题

现有 `check_saved_search_bodies.py` 绑定旧 `model-led-primary-v1` 搜索结果，最多返回三项 1800 字片段，且已经有防重复 marker。它适合当时的故障复核，不是任意新一期资料的通用验收入口。原通用提取预检只用 `find_spec`，安装过包但依赖损坏也可能显示已安装。旧打包器还要求 v19 原包，不能凭它证明与已部署 v20 兼容。

本轮增加通用离线验收入口，复用生产解析器与现有响应快照格式，不重发请求；并增加只接受已确认 v20 原包的合并升级准备工具。没有修改既有试验 marker、失败台账、调度或模型预算。

## 新入口与结果含义

在项目 backend 目录，用该项目自己的 Python 运行：

```bash
python -m app.reading_acceptance
```

无参数只实际导入可选库、读取安装版本，区分未安装、缺失间接依赖和运行库加载异常。它不会安装依赖、提取网页或联网。退出 0 仅代表可导入；退出 2 代表未就绪，错误正文不回显。原 `capabilities()` 新增 `generic_extractor_runtime`，保留 `generic_extractor_installed` 兼容旧调用方。

复核某一期实际保存的响应（将 `episode-实际目录` 换成已有目录名）：

```bash
python -m app.reading_acceptance \
  --captures data/episodes/episode-实际目录/public-responses \
  --hours 72 --write-review
```

没有 `--write-review` 时只读，不生成报告。指定后，在原 `public-responses` 目录内新建私有 `reading-review-*` 子目录，包含 `result.json` 与 `review.md`；原始 HTML、metadata 及历史报告不覆盖。报告包含全部提取文字，属于第三方私有临时材料，随原 episode 生命周期清理，不上传 Git。任意其他快照目录也可读取，但不在 episode 下时不自动享有 episode 清理机制，须由操作者管理保留期限。

输入契约沿用 `capture_public_response()`：一项 JSON metadata 指向同目录 `.body` 文件，包含真实 `url/http_status/content_type/bytes/body_sha256/observed_at/snapshot_cutoff/file`。工具不会凭标题、摘要、URL日期或重放时间补造原始字段。

具体检查包括：

- 原始字节数与 SHA256 一致、HTTP 200、HTML 类型；单文件不超过 2 MiB、元数据不超过 64 KiB、默认总读取 64 MiB。预算耗尽逐条记 `not_attempted`，不冒充解析失败或自动继续扫描。字节上限是本地处理预算，不是节目选题配额。
- 只读同目录普通文件，拒绝路径跳出和软链；不按 metadata 路径读取外部文件。
- 复用生产正文解析、访问限制、发布日期和窗口规则；论坛与研报摘要交给专用读取流程，不升级成新闻。
- 记录全部解析正文、来源、原时点说明、正文 hash、短讯或可见正文等范围；正文后部供人工核对，不只输出首段。
- 同 URL、同原始响应、同截止的重复快照只计一次，不推断跨媒体语义同事件。
- 原观察时间与截止时间不刷新；响应取得晚于截止时单独标记，不能据此声称该版本当时已可见。

没有文件返回 `no_captures`，不是成功验收；缺日期或解析失败逐项记安全错误码，绝不回退联网。CLI 退出 0 只说明至少有一份解析准入正文待人工审阅，**不是所有条目通过、覆盖充分、事实正确或可以启动收费试验**。`content_accepted` 与 `paid_trial_authorized` 始终为 false，保留人工验收边界。终端只打印汇总，全文留在私有报告。

## 合并升级范围与门槛

新增 `tools/build_reading_acceptance_release.py`，把尚未部署的检索目的/实际执行账本、通用提取和依赖清单、本轮验收入口合并为一个源码更新。只接受完整原始 v20 ZIP，SHA256 必须是交接文档确认的：

`133dd38ec86f85377ec5c396c93bc4fc2a380b22a1c59dabc56230913aba7804`

工具读取原始 manifest/payload，并校验每个基线文件；新增文件预期不存在，已部署文件使用原包实际 hash，绝不拿服务器当前文件或近似 Git 提交补成基线。安装器仍默认只读验证，任何未知服务器差异均停止。保留 `.env`、App 数据库、维护暂停和旧试验标记。

示例仅供后续准备交付，**本轮未执行**：

```bash
python tools/build_reading_acceptance_release.py \
  --baseline 交接保存的原始v20.zip \
  --output 交付目录/finance-reading-acceptance
```

生成包不等于安装、演练或服务器验收。新工具不内置构建/编译/测试/安装演练，不安装 pip 包、不重启服务；manifest 明确记录源码是否有未提交改动、未演练/未测试/未服务器验证。没有原包就停止，不要求用户再上传一两个源码的小包。

本轮下载的源码交付 ZIP 是开发源码副本，**不能直接覆盖生产目录，也不是上述可安装增量包**。生产合并包还需要原始 v20 交付物。
