# 通用取材反馈循环（2026-10-31，未部署）

## 目标与本轮边界

用户明确纠正：要改的是每天可复用的收集、选择、阅读和补查能力，不能靠人工补本期报道证明能力完善。本轮没有新抓文章、没有为本期事件加固定查询或网页模板。修改的是既有模型取材器 `discover` 的执行循环，以及它向报告交接证据的方法。

旧取材器已经能多轮调工具，但完整性主要由模型自行声明；上一轮新增的 `material_followup` 只是报告输入后的建议，没有驱动取材继续。本轮将依据真实回执计算的 `collection_feedback` 接到取材器每轮输入和结束判断中。它仍依赖模型的选材判断，不是程序能机械判断重要性或事实充分性的声明。

## 运行路径

```text
现有 discover_current / 显式隔离 runner
  → 当前 App 名单、原始截止、既有预算
  → 程序依据实际回执计算本轮缺口
  → 模型按任务选择具体查询、候选来源或本地补读
  → 原工具执行；精确 URL/查询复用及失败保护继续生效
  → 按预算补读已存正文缺少区间
  → 重算缺口，交给下一轮模型
  → finish 核对阅读关联、准入与剩余任务
      ├─ 有可执行缺口且没有说明取舍：反馈并继续原剩余轮次
      ├─ 明确取舍或最后轮次仍有缺口：只交部分材料
      └─ 不支持的证据/虚报范围、反复无进展：停止，不导出成功结果
  → 只将底稿实际引用且合格的正文导出给报告入口
```

这条逻辑已接在现有 `discover()` 内，每次调用都会执行；不是新增一个供人查看、与主流程无关的检查工具。没有切换旧 scheduler、恢复生产、启动服务或添加公网触发入口。

## 程序具体检查什么

新 `discovery_feedback` 从实际工具回执核对证据 ID、返回片段、原存储正文及 SHA，合并真正提供过的字符区间。依据这些区间记录未提供的前段、中段和后段，保存的是完整正文不会自动变成“模型读完全文”。

研究范围使用当期传入的七类任务和当前 App 自选股；不把某次历史名单、股票、事件或日期写入生产代码。每个公司缺口都用当前 `market:code` 标识。公司直接阅读、行业用途、市场来源关联分别记账；公司名在正文出现不代表主体已核实。后续复用搜索新增范围时，不会追溯修改之前阅读回执的研究关联。

有目录无正文时，反馈保留尚未读取且适合 HTML 阅读的候选 ID，供模型按重要性选择；失败来源从这组候选中移出，在原预算允许时建议另找来源。程序不机械读取首条，不自动重试失败 URL。目录页、文档和社交页面仍走既有能力边界。

市场仅有短讯时会要求核对驱动；行业不能仅因公司稿出现行业词就自动填满。反馈也展示相同正文 hash 的多 URL，但不因不同域名就声称独立印证。所有范围记录均保留 `subject_verified=false / coverage_sufficient=false`。

## 自动本地补读与成本

初次 URL 阅读仍最多返回 4,000 字符。之后程序调用共用的 `complete_local_reads()`，按真实未提供区间读取同一已存正文；不重新请求 URL，也不为一次本地补读单独买一轮模型决策。

新增 `Limits.local_read_characters`，默认整期 12,000，允许 0—48,000；显式 `read_more` 与自动补读共用该额度。补读还受原始输入字符上限、预留空间和总截止时间限制。额度不足就保留未读区间，不删原文，不将局部读取标为完成。首次各 URL 片段仍由既有 URL 次数与输入上限共同限制，该字段不是本期全部输入 token 或金额上限。

模型轮次、搜索、URL、输出和总时长原上限没有增加。重复缓存操作连续两轮没有新的检索关联、尝试或阅读区间，就以 `stalled_no_new_evidence` 停止。重复提交相同的过早结束、没有新进展或有效取舍也停止；不是把所有剩余轮次花在重复解释缺口上。

暂停、共享模型预算、原收费 runner 的显式授权/指纹/名单检查和固定旧 trial marker 均保留。新增参数和提示词会使未开始但旧版本的预览指纹失配，须重新审阅；不能据此重开已失败 trial。

## 结束判断与编辑取舍

协议增加可选 `deferred_tasks`，逐项引用程序给出的任务 ID 并写编辑理由。它是待审的取舍，不是证明没有消息，也不会提高范围的充分性标记。

`finish` 引用的正文须通过机械准入，不能引用推广提示未处理的正文；声称 `body_provided` 的范围须有相应实际阅读关联，声称 `searched` 须有成功搜索回执。基本 JSON、证据 ID 和覆盖结构错误继续停止，不启动额外修复请求。

仍有可执行缺口且未说明取舍时，反馈进入下一轮；使用原有剩余模型额度，最后一轮不再加轮。最后一轮可保留缺口交部分材料，但不能豁免错误引用、推广或虚报范围。未提供全文、短讯驱动、未取正文等问题保留在 `open_tasks`，不会改写为“全部完成”。

## 报告交接修正

此前导出全部读过的正文，导致取材时碰过推广稿，即使换了合格来源，推广稿仍可能挡住整个报告生成。现在从底稿 `events/coverage/watchlist_checks` 的实际引用集合选择证据，并重新检查正文与回执。被舍弃的阅读记录和原文留在取材工作集，报告交接仅带 `unselected_provided_ids`；不会混入报告工作集。

选中正文仍保留全部存储文字、原证据 ID、SHA、原截止和观察时间，不按模型摘要裁剪。`reading_coverage` 记录真正提供过的区间和未提供部分；`collection_feedback/open_tasks` 同时进入报告预览、写作和审查。程序不会因为本文描述了读完能力，就宣称下游模型认真阅读或新闻已独立核实。

## 本轮实际执行与尚未验收

实际对两组真实保存的主资料执行了本地阅读业务，分别包含原有 3 份和后续 7 份正文。没有合成网页，没有注入模拟模型决策，没有新 GET、搜索、收费模型或 TTS 请求。

第二组一份 10,743 字符长文首次提供 4,000 字符；通用补读函数按实际缺口追加两段，共 6,743 字符。保存的实际阅读区间覆盖全文，原正文 hash 不变。其他短正文初次已全部提供，无额外补读。这只验证了已存资料上的补读行为，**不是新日期自动取材或整期报告验收**。

已编写覆盖动态 A/H 名单及不同日期、过早结束继续、无进展止损、长文末段、局部预算耗尽、错误范围声明、推广稿换源后导出选择的回归用例，并更新旧用例的显式取舍协议。按会话约定，未运行测试、构建、类型检查或 lint。因此新循环的模型选择效果、真实搜索换源和跨日期适应性仍待实网验证，不能报告为通过。

未调用收费模型，未改生产暂停，未部署或推送。新增模块只依赖现有项目和标准库；累计源码含前几轮改动，不能直接覆盖生产。合并准备工具已同步模块和文档，但仍要求真实部署基线齐全，缺失则停止。本轮无已启用 Skill 调用本项目接口，无需同步 Skill。

下一步应在明确环境、当期 App 名单和预算后，走上述同一入口做新日期真实取材；观察程序是否独立发现缺口、选择来源、读到后部并保留正确边界。不能再由人工补材料代替此项验收。
