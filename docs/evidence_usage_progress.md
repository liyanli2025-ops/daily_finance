## 本轮修复

原先检索工作区保存所有候选，但成功后的来源清单主要来自搜索/阅读工具的访问记录，初始选入的资料没有完整记入；访问记录也不能区分搜索片段与整篇存储正文。

现在对初始新闻、研究底稿、跨市场资料、搜索返回片段与追加阅读，记录存储正文的SHA256、字符范围和渠道。重叠阅读合并，不重复累加。超出正文末尾的读取返回out_of_range，不再把资料授权为已访问。

- prepared：片段已组装或工具已返回；尚不能断言模型请求成功。
- confirmed：携带这些片段的分析请求返回完整非空回复。请求失败时，未确认的范围仍保持未确认。轮次数不是HTTP次数，也不是计费依据。
- reading_scope：采集到的是原文、RSS文本、研报摘要或节选。
- model_input_scope：对该份存储文本，是全部提供、部分提供还是未确认。摘要100%提供不等于完整原文。
- cited与decisions：正文引用、结构化判断的支持及反证ID，分别与确认范围核对。未确认范围的引用会列出，不能用“在资料池中”替代“提供过证据”。

这不是模型注意力记录、论据有效性证明或事实核验结果；也不能判断未完成请求是否已经被服务商接收/计费。数字行情和技术指标仍由既有带时点的市场快照审计，本清单主要记录新闻与研究文本。

## 保存与查看

审查诊断metadata.evidence_usage、生成检查点evidence_usage和当期工作区usage.json保存记录。成功来源清单包含初始材料；成功后仍清理工作区的正文/检索全文，工作区按既有24小时期限清理。审计清单不再次加入模型提示词。

只读本地文件：

```bash
python -m app.evidence_usage_check --case /实际路径/review-某次.json
```

该命令不加载配置、不读App数据库、不联网、不调用模型或TTS、不修改文件。也可读当期usage.json。旧诊断缺少范围时返回unknown_historical_scope，不能通过历史收集数量倒推阅读覆盖。冻结验收输入只有与当前节选逐字匹配时才登记范围。
