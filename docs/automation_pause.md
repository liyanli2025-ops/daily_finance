# 修改期间暂停财经自动化

用户明确要求修改完成前暂停此前的每日自动采集/生成，避免继续消耗模型。此前“只限制调试，保留线上定时”的约束已被本次要求更新；恢复必须得到用户明确同意，不能因测试通过自动恢复。

后端原先无暂停开关，lifespan每次启动注册早晚报告、午间预采集、自选股更新、历史信号任务与整点公开采样。早晚任务包含模型分析和口播，不是只采集公开数据。截图API时间的时区和每条归属尚未核对，不把截图所有费用直接归于某一任务。

## 新维护标记

`/var/www/finance-daily/backend/data/.automation-paused`存在时：

- 启动仍初始化数据库、报告/音频静态目录及App路由，但不启动SchedulerService，因此以上自动任务不注册。
- model_gateway在解析模型路由、创建HTTP客户端和预留调用计数之前拦截，并在每次重试前重新检查标记；analysis/review/extraction/podcast全部受控，不换其他服务商继续调用。
- health预期为status=healthy、database=connected、scheduler=stopped、automation_paused=true。
- 当前代码不会自行删除标记，现有缓存清理也不匹配该文件。服务/机器重启不会恢复财经调度；未来代码安装不应撤回暂停防护。

只控制本财经项目，不修改其他项目、模型密钥、App数据库或定时任务配置值。已经发出的外部请求不能靠标记撤销。暂停不代表能阻止其他项目使用同一服务商账户。

## 部署与边界

tools/pause_finance_automation.py只接受当前已知或已应用的main.py、model_gateway.py哈希，预先验证两文件和Python语法，私有备份，原子写入并保留文件权限；生成持久标记。函数本身不远程访问、不调用模型、不改其他目录；服务器命令随后只重启finance-daily并读取本地health。

暂停操作尚待用户在服务器执行并贴回health确认，不能说线上已经停好。生成的暂停命令可以直接粘贴，不依赖GitHub下载或新上传包。若为立即停止费用而先systemctl stop finance-daily，财经App接口会暂时离线；完整命令应用后再恢复App访问，维持自动化与模型暂停。若无法安全完成配置，命令的失败处理保持财经服务停止，不回退为自动运行。

354项离线程序回归通过，包括真实生命周期的暂停/正常分支（DB和调度副作用模拟）、四类模型任务网络前拦截、重试期间出现标记、校验失败不覆盖、备份、重复应用及配置/数据库保留。实际已知两份源码的补丁另经隔离应用演练通过，本轮无真实模型或TTS调用。

## 恢复

当前不要执行恢复。只有用户明确同意后，删除该项目的暂停标记并重启finance-daily；检查health和下一次运行时间，不为恢复验证主动生成整期。不要更改或删除模型密钥来实现暂停。
