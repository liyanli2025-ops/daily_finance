# 全池发现与按预算初读：取消固定28篇

用户要求：不能用28篇作为市场覆盖完成标准；先发现完整候选池的重要事件，再按问题阅读。源码取消固定28总篇数限制，保留成本保护。不是把28改成另一个篇数，也不是将全部全文一次灌入。

## 实现

- 每份通过正文准入的候选均有完整标题、来源日期、来源和存储阅读范围的目录记录，不截标题。相同公司披露/监管批次/统计发布/原文URL按已有窄规则生成线索组，其余不强行语义聚类；线索组不是事实核验或独立事件数。
- 目录编号Cxxxx在本期绑定唯一完整证据ID，可read_material直接定位；读取返回完整ID、正文与范围，再引用[N:完整ID]。目录本身不登记为正文已读，也不能据标题填事实。搜索仍覆盖全部合格原文及研究资料。
- 市场覆盖、经营证据和公司材料按原有阅读优先顺序，使用实际渲染字符数决定能放入多少正文。市场线索正文预算1800、当前公司2200、其他1200/700，均保留完整句与字符范围；不是逐篇均分1.8万字符。各数值是工程阅读预算，不是最优性或覆盖充分的证据。
- news_initial_prompt_characters默认34000，涵盖目录、正文块与新闻说明；目录先完整准备，正文在剩余空间内安排。不凑满名额。完整目录装不下或最终文本超预算则在模型请求前停止，不静默裁掉后半候选。
- 正式分析初次请求看到目录；有重要缺口时按既有取材协议请求原文，最多两轮的既有上限未增。后续请求保留原问题、请求理由和真实工具返回，省去已用于发现的全池目录；不假装依靠隐藏记忆保留全部线索。模型也可能直接成稿，是否有效取舍仍需实际验收。
- 审查继续看到已提供正文与补读证据，不重发未读标题。完整目录及映射保留在诊断中。额外未读材料不能凭目录计作事实核验。
- 未增加独立模型阶段、不改变零重试和禁自动整篇修稿。每次HTTP仍检查100000字符保护；字符不等于token或费用。
