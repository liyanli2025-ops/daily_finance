# 从投资者的问题出发研究，再决定节目选题

2026-10-31。源码与免费回放更新；未部署服务器，未恢复自动化，未调用用户的模型、TTS或付费搜索。

## 用户真正需要得到什么

面向A/H市场、日内到数日交易的个人播客。用户的自选股随App变化，但研究不能只围着自选股转。
听完应能回答：当期什么变化最重要，市场可能在重新评估什么，怎样影响自己关注的方向，有什么竞争解释，下一交易时段观察什么会改变判断。
允许有倾向的判断，但不得编造事实、预期、资金行为或“未定价”。重要性不能用新闻篇数、标题热度、公司财报数量衡量。

研究层要广，节目层才做取舍。不能因为口播要简短，就让研究一开始只剩一两件事或8篇正文。
既有完整候选目录和可补读池继续保留；不恢复28篇上限，不承诺某个篇数就代表覆盖充分。

## 已落实到正式路径

1. `episode_research.initial_prompt`是分析请求和成本预检共同使用的完整提示词入口。
2. `research_desk`要求模型同时留下研究底稿和节目取舍：A股、港股、海外、宏观政策、行业、重大公司风险、动态名单、价格结构的实际检查范围；每个选题的变化、决策意义、传导、竞争解释、观察条件与引用。
3. 每次取材请求也附研究状态。完成时用`complete_research`同时交底稿与原格式报告；不额外固定增加一次主编模型调用。
4. 已明确承认的高优先级入选问题若仍需补读/补查，程序保留底稿并停止成稿，不自动增加收费请求。没有实际选题记录、引用不存在/未提供正文的材料，同样停止。
5. `read_materials`可以批量补读全池中的材料。每包最多12项、正文18000字符、每项6000字符，是工具包和请求长度保护，不是全天文章上限；实际读取位置继续记录。
6. `search_public`明确只是华尔街见闻/证券时报的既有定向查询，不冒称全网搜索。
7. 新增`search_web`和`read_public_url`两个独立能力：搜索只返回发现目录；网页只有通过正文/来源日期核对，才能加入当期证据池。标题或搜索摘要不会直接变成正文。

模型研究底稿保存于当期私有`data/episodes/episode-*/research-dossier.json`，跟随既有24小时资料生命周期，不朗读给用户，不提交GitHub。
`confirmed`只表示某些字符范围随一次正常完成的分析请求提供过，不代表模型注意到了、读完了全文或独立验证了事实。
程序核对记录与实际提供范围；它不能证明模型认为重要的事情真的重要，不能证明因果、独立性、覆盖全网或预测准确。

## 新闻鉴别原则

- 美股和重要外盘是独立研究范围，不只作为A/H背景，也不只搜科技财报。正式`research_desk.INSTRUCTIONS`已加入行情/跨资产、政策宏观、公司产业、重大舆情、国际事件的检查要求；`episode_research.questions`同步提醒，分析和成本预检仍共用`initial_prompt`。全球重大事件即使暂无直接A/H传导证据也可保留，注明关联待核，不强行套到自选股。
- 外盘关注价格分化、利率/汇率/商品/信用与股市的相互印证或冲突；机构观点、做空/调查、诉讼与传闻追到来源和回应，未确认线索单列。必须区分交易日、时区、盘前/盘中/收盘/盘后和节目截止，禁止用后来消息解释此前A/H行情。
- `global`覆盖说明须交代检查过的方向与缺口，不以单条联储新闻代替外盘研究。此次仅修改提示词，没有新增硬性字段、地区/篇数配额或收费阶段；程序结构检查仍不能证明模型确实全面研究、事实正确或判断专业。没有新增源接入，也未部署服务器或恢复自动任务。
- 本次提示词调整后，研究底稿/取材流程的24项离线回归通过；模型为模拟调用，不是新的真实模型质量验收。
- 先调查市场主线与分歧，以及政策、利率、汇率、商品、海外重要公司向A/H的传导，再检查行业和动态自选股敞口。
- 普通财报不是自动入选理由。需要拆基数、并表、环比、经营指引、现金流、可查预期与价格反应；没有预期数据就不能宣称超预期。
- 非自选公司须有行业代表性、重大事件或风险传染的具体理由；不是因为有一份新财报就占节目位置。
- 同题材料保留有增量和反证的部分。公告和记者报道可以互补，转述不能重复算成独立核实。
- 可以留意弱信号，但要说明线索、可能影响、缺失环节和后续观察；报道少不能推出市场没定价。
- 找不到公司新消息可以接受；工具不可用不能解释成公司没有消息。没有新事实的股票不必逐只凑内容。

## 通用搜索的真实状态与费用

实现了Tavily新闻搜索适配器，按[官方Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)的公开协议编写；**尚无本地账号配置，没有进行真实API验收**。
它不是现有Ofox模型自动附带的能力，也不是当前聊天的联网工具。

默认配置：

```dotenv
RESEARCH_WEB_SEARCH_ENABLED=false
RESEARCH_WEB_SEARCH_API_KEY=
RESEARCH_WEB_SEARCH_MAX_REQUESTS=4
```

不开启或没有独立搜索密钥时零搜索请求。不可把Ofox密钥填到这个字段。
后续是否使用这个服务、账号额度及实际扣费，应另行明确后再启用；当前改动不要求用户充值或立即配置新账号。
每个当期工作集最多4次搜索HTTP尝试，失败计数，同词缓存复用，无自动重试。启用后搜索可能独立计费，并不包含在模型调用次数里。
既有分析最多3次调用/2轮取材及网关字符保护保留。新底稿增加输入和输出量；“没有固定额外调用”不等于免费，也不等于保证总费用降低。
成本回放已改用同一个完整提示词入口，避免漏算研究协议；补读后的每个请求仍分别预检。

免费探测过Bing RSS搜索：中文财经查询返回大量日历/百科，英文财报查询返回购物/登录首页。HTTP 200但相关性不合格，已弃用，不接生产也不反复探测。

## 公开网页读取验收到哪里

复用已验证媒体解析器；另验证了新浪`#artibody`正文和原始发布时间、BEA发布正文与明确带EDT/EST的发布时间。
通用页要求可识别正文、标题和文章发布日期；日精度/分钟精度保留，不用URL日期、搜索摘要、页面修改日期冒充发布时间。
只读公开HTML，限制大小、跳转和时间；拒绝内网目标，连接固定到核验后的公网地址，每次跳转重新核验，不携带应用或搜索账户密钥。
失败页面记录暂停，不自动反复请求；旧失败台账仍生效。HTTP成功、可见正文和完整/独立原文是不同状态。

使用上一轮新采集样本中的16个已保存HTML，**零网络重放**：

| 结果 | 页面范围 |
| --- | --- |
| 6个取得可见正文与来源时间 | A股收评、美股收评、全球科技财报报道、港股收评、BEA收入/支出发布、中东与原油报道 |
| 10个未自动接纳 | 另有页面缺可识别正文/日期、加载页或尚不支持的模板；保留未读状态 |

这只验证新读取路径，不能把6个页面当成一整期节目覆盖量；也不能把10个页面未接纳解释成10家媒体都失效。
既有固定采集和ResearchHub文档读取路径继续独立存在。新URL读取器尚未接通用PDF读取，亦不执行网页JavaScript；不能声称能读取任意链接。
另外使用新连接路径对已成功过的BEA页面进行一次免费真实读取：HTTP 200，取得3554字符正文及原始发布时间。仅验证本地连接/该页面解析，不等于腾讯云网络或其他模板通过。失败记录保留可操作的安全错误码（HTTP状态、缺日期/正文等），不只剩ValueError，也不保存供应商报错原文或密钥。
私人原文留在本地outputs，不上传第三方全文。

本轮完整离线回归678项通过，包含App名单到报告/口播的数据流、来源范围、失败暂停、费用保护和新研究协议；外部收费调用使用模拟。这不能代替一次真实的新资料研究与听感验收。

## 下一位AI怎么继续

先读本文件和最新`AI_HANDOFF.md`，不要被旧日期的进度/安装包描述带偏。

1. 优先补齐已明确缺失的正文模板或原始披露读取，用已有失败材料免费回放；不要反复请求旧失败URL。
2. 明确一个服务器实际可用的通用搜索入口，再做一次有上限的搜索相关性与正文联合验收。适配器存在不代表服务可用。
3. 合并部署前仍保留暂停，运行`python -m app.research_desk_check`和现有选材/费用回放；该命令默认只检查能力配置，不联网、不调用模型、不写App。
4. 下一次真实模型验证必须使用完整新采集的市场、海外、行业、动态名单与行情；先检查全文/片段、转载、关键缺口及完整请求费用。不要继续在旧人工修正版上循环写口播。
5. 有限真实调用时检查新研究协议能否执行、是否主动发现遗漏、取材是否改变判断、重点是否专业且有用；底稿合规不自动等于质量通过。仍禁止自动重试/整篇修稿。
6. 再验证报告到自然口播、音频听感、前端播放及晨晚复用；最后才讨论恢复定时任务。预测效果需要多期跟踪，不能从一次样稿宣称胜率。

旧的独立单主题/人工样稿脚本若直接调用模型，不经过`complete_with_research`，就不验收这个新研究流程。
