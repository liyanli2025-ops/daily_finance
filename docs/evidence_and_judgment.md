# 资料质量与有方向的判断

本轮目标是让实际输入可检查，允许有依据的主观分析。计数、自动分类、审查分数与测试通过都不代表交易价值、预测准确率或收听质量。

## 已实现

- RSS保留真实短文本，不把不足50字的内容替换成标题。只有标题或空文本不能入模；短小的官方操作公告仍可使用。长RSS仍按摘要使用，未读取完整研报仍按摘要使用。
- 采集去重及正文筛选都识别至少80字符的相同正文，防止改标题转载反复占位。同标题但实质正文不同的已读取原文保留，避免删除后续进展或反面材料。不同数字、正负方向不能被标准化抹掉。没有声称完成语义事件聚类；改写转载仍可能漏过。
- 财经与跨界输入共用标题排除和阅读范围标记，跨界不重复提供财经已选正文。新闻输入不再附加自动利好/利空标签，保留实际采集文本，不在入模时再截成500字。
- 研报摘要不再自动填满两个背景名额；仅补充关联当前公司、已选主题或已匹配经营环节的材料。无关的行业/个股研报不为凑数入模。
- 每期输入包含覆盖核对：已读原文、RSS/研报摘要、短文、重复正文、主题集中度，及当前App每只自选股的公司专属原文、行业经营环节原文、综述提及和仅摘要。缺口限定为本次入模新闻；研究缓存及技术行情另查，不能推断公司没有消息。
- 写作和审查均允许有方向、尚待确认的假设。主假设要与最有力的竞争解释比较，区分当前支持与未来验证，不要求等所有信号齐全。RSI传统超卖术语与估值便宜、未来反弹分开。预测标记不能豁免事实错误或毫无支持的猜测。
- 完整初稿及修复回复在解析或下一次付费请求前私有保存；不完整的在途回复无法靠此恢复，也不会被自动发布。

## 无模型费用检查

先检查已经保存的生产采集，不再抓取或调用分析模型：

```bash
cd /var/www/finance-daily/backend && sudo ./venv/bin/python -m app.evidence_check
```

读取`backend/data/radar/news-acceptance.json`，按当前App自选股与缓存画像回放，输出并私有保存`backend/data/radar/evidence-audit.json`。显示原始快照日期，不能称为刚刷新。旧快照若只保留去重后文章，就不能还原去重前漏斗；正文预览不接受为完整快照。

需要更新资料时再运行一次公开数据验收，零模型/TTS请求：

```bash
cd /var/www/finance-daily/backend && sudo ./venv/bin/python -m app.radar_check --hours 72 --full-news
```

新快照保留窗口内去重前文本、采集漏斗、入选阅读范围、逐股覆盖缺口，以及实际提供给作者的完整新闻输入。该命令不是报告生成，不自动启动付费验收。

## 仍不能据此宣称完成

不同文本不等于独立事件，不同网站不等于独立采访；全文也可能低质或不实。当前新闻量不证明市场信息完整。日内资金、市场宽度、盘中技术数据等未核验模块仍缺失，日线只能支持其截止时点的判断。港股公司一手披露及完整行业覆盖也不能据本轮修复宣称齐备。

真正的报告验收仍须逐条核对：是否有新变化、是否改变原判断、为何更倾向一种解释、反证是否处理、口播是否可听。预测准确性需要留存原始对象、期限、条件和后续结果；本轮没有新增付费样本，尚不能证明这些效果。
