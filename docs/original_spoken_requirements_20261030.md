# 旧版口播要求回溯与恢复

依据：改造前提交 `918b3661576786b27e29c047eaca7ed2bb790f3c` 的 `backend/app/services/podcast_generator.py`，以及 `.codebuddy/plans/优化播客天气格式和报告深度_e729c0c1.md`。这是仓库记录，不表示所有代码措辞都是用户逐字提出。

## 应保留的产品要求

- 一条清晰主线贯穿全篇，不按报告模块逐项播报，自然过渡。
- 像面对面聊天，分析深入、表达通俗；每个重点解释对短线选择的意义。
- 早报信息密集，适合通勤，服务当天应对；晚报复盘发生了什么、为什么、原判断需如何修正、下一交易时段如何准备。
- 科普从本期实际案例引出，不插无关课堂；开头随内容变化，不介绍主播身份或节目名；结尾自然有温度。
- 可直接朗读的纯文本、自然数字单位、段间停顿，不朗读导演备注。

## 按后续用户要求修正旧设计

不用20年经验人设、强制昵称次数或天气失败时编造天气。旧版强制目标价/仓位/买卖信号不恢复；保留有依据的判断和应对，不让口播阶段新增交易指令。旧文档10—15分钟及分早晚字数仅作历史参考，当前按内容决定长度，最多20分钟，不凑字数。

## 本轮修改

重写正式 SPOKEN_POLICY，按叙事、实用判断、交谈表达组织，替换上一版规则而非继续追加长清单。开场判断后直接展开，避免再次“先说结论”；选题共同推进一个问题，不等于三个模块。要求编排中省略的数值在正文兑现。保留重要反证、归属、时点与条件，不以口语化删掉实质限制。

删除过宽的信用条件解释示例，明确相对利差不能自动推出实际成本或融资难度。限制口播把“偏谨慎”扩写成源报告没有的追高/减仓指令。

## 验收边界与下一步

这是正式写稿提示词调整，不是新的分析能力或音频质量验收。历史 v2 结果仍保留，不重跑、不删除付费标记。未调用模型、TTS、采集或恢复调度。

先在后续合并部署时纳入。下一次必要的口播验证须使用新输入指纹和新试验编号，单次授权，不自动重试；人工看主线是否推进、是否有重复总结/数字堆砌、应对是否忠于报告、编排取舍是否兑现，再决定是否合成音频。不要用离线测试通过宣称听感已经达标。

离线验证：582项测试通过；提示词契约、编排解析及缓存相关回归通过，不等于自然度或事实准确性已由真实模型验证。
