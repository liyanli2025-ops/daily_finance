# 财经日报流程收敛决策与验收约束

状态：整体审查完成，以下架构改造待实现。本文不代表取材、成稿、音频已经端到端验收。

## 要解决的具体问题

用户需要每天能理解的重要财经事件、与自选股的关系及可听节目。目前代码改善了读取和协议校验，但实际运行仍可能花费多轮调用，只得到部分材料；重要事件漏报、已有成果不可见、生产与验收路径不一致没有得到解决。

本次审查基于 `2ddd414fa5988f93fa2adfc3573f3473dc8f9e92` 的代码和用户上传的四段真实运行结果，不新增联网取材，不核实附件新闻本身的真实性。

## 保留与停止扩展

保留同 URL 缓存、完整原始响应、去重、正文原文区间、发布时间与交易时段区分、来源用途、主体匹配、推广提示、名单签名、私有失败记录、零自动重试、暂停保护、已审口播缓存和音频有效性检查。

停止将下列做法作为新一期的默认路径：每次读取都让模型重新决定；反复发送大段历史上下文修 finish 字段；用类目覆盖代替重要事件覆盖；每次失败都新增一个独立付费 runner；更名重跑或清标记；文字通过后再从头写一版口播稿。旧 runner 保留历史复核用途，不删除原始记录。

## 同一个整合改动应实现的路径

1. **免费准备。** 冻结 App 名单、截止时间、报告类型、源码与模型路由。展示当期阶段、搜索与读取边界、模型价格依据、TTS 路线及费用未知项。准备不产生服务商请求。没有可审阅的费用边界时不能进入收费执行。
2. **本地程序批量执行基础搜索。** 在已批准搜索额度内查询市场底图、自选股、国内及国际重大动态。跨类目的重大事件发现单独列项，不能只靠“利率、关税、收益率”几个关键词。每条结果保留网址、标题、时间与摘要，不把摘要升格为正文。
3. **模型第 1 次：形成事件选题单与读取计划。** 合并同事件转载，标明重要性、可访问候选、待核问题和选择理由。列出高重要性项目，即使它尚无正文；不能只列成功读取或想写的事件。执行器批量读取选定候选，优先同 URL 缓存，换独立来源而不重复失败 URL。
4. **模型第 2 次：审视证据与重要遗漏。** 按事件核对实际正文、时间口径、反方及影响；每个重要选题必须明确为可写、补查、延期或排除，并有证据或具体原因。一个范围有另一篇正文，不能自动消掉本事件缺口。大类和公司覆盖仍保留，但不再单独决定“足够”。
5. **仅有必要时追加一次补查判断。** 第 2 次提出的具体搜索或读取包由程序执行，已有正文补读不重新下载。新增一次模型检查补查后的事件账本；仍缺重要证据就交部分成果并停止成品生成，不继续 finish 循环。追加请求计入同一期封套，不重置历史用量。
6. **模型写作 1 次。** 在证据条件满足时，同次返回文字稿、口播稿、各自的事实引用与时段标签。只传选用原文、必要反证及明确缺口，全文仍存于工作区；不能为省 token 删除反方、把未提供内容当作已读。
7. **模型审稿 1 次。** 联合审阅文字与口播的事实、因果、交易时段、重要遗漏和听感。程序另外核逐字引用、ID、数值关系、长度与结构。完整返回且通过才生成可供 TTS 的已审口播缓存。审稿失败保留问题和稿件，返回需修订；不自动再收费修稿或再审。
8. **TTS 与交付。** 直接使用审过且 hash 绑定的口播稿，不另起模型改写和审阅。TTS 单独计量；失败保留已审稿，下一次只处理失败阶段。交付包含可读文字、音频、事件清单、缺口和费用回执。发布及恢复定时任务仍是独立操作。

正常路径目标为 4 次模型请求：选题、证据评估、联合写作、联合审稿；重要缺口允许同一封套内追加 1 次。搜索和网页并行执行本身不需要多一次模型。**该次数是有边界验收的设计目标，尚未实现，也不能保证 4 或 5 次足以处理任何新闻日。** 重大事件不能核实就明确停在部分成果；若发现反复因额度不足影响覆盖，应重审设计和费用，不悄悄增加请求。

## 一期数据与费用必须如何归并

统一一期 ID、source cutoff、名单签名及阶段状态；取材、写稿、审稿、TTS 共用一个持久化账本和进程锁。正常服务、手动入口、验收入口都委托同一编排服务；入口仅负责触发与展示，不能各自复制收费实现。

事件账本至少保存 event ID、候选、重要性及理由、选择/排除/延期状态、实际正文与逐字依据、失败及替代来源、交易或发布时段、最终稿段落映射。来源目录和实际送入模型的区间继续分开。每次请求记录服务商请求标识（可用时）、阶段、目的、token、缓存、请求估计费用、已知实际费用及未知状态；不能把同一次续审与原写稿重复相加。

模型、搜索、TTS 分列。尝试前预留剩余阶段，失败/未知用量不直接当作零，余额拒绝不自动重试；续接只能使用同一封套的剩余部分。模型请求次数、字符和预留输出不能称为美元硬上限。

服务商明确支持且可核对的账户/Key 预算隔离才可作为账单金额硬边界；本地估价只能声明为估价。价格或计数方法不清楚时，预览列出未知项，不能猜价格或按免费计算；没有用户明确接受的估算边界或可验证的服务商金额限额就不收费运行。本轮不要求用户充值。

## 实现范围与唯一验收出口

改造应集中在统一编排服务，复用 existing collector/discovery/report/podcast helpers；同时改 scheduler 和手动生成入口，使所有入口复用该服务。不要再仅向 tools 增加一个可独立付费入口。

交付前必须具备以下可审查项，未具备不安排下一次收费试跑：

- 已有附件的离线对照：动态事件账本能显式留下中期选举缺口；超时不等于没有事件，评论不当原披露、旧收盘不充新收盘、推广不补公司覆盖。
- 本地纯替身的同一主入口验收：批量成功、重要来源失败、补查仍缺、402、引用审查失败、TTS 失败及只续接失败阶段。验证无请求外漏、金额未知不宣称已限额、不越封套。此处是待执行要求，本轮未运行用例。
- 免费预览展示统一一期 ID、当前 App 名单、截止、实际事件/来源/缺口、各阶段请求计划、费用依据与未知项；保留暂停。
- 用户能在收费前看到输入、计划和边界。准备齐全后，再提交一个整合版本和一组服务器步骤；不继续十几个临时包轮流上传。

之后只做一次当前日期、真实名单的完整受控验收：先看事件与全文，再看稿与口播，审过才 TTS；每阶段即时保存、可读导出。若重大遗漏、账本不符或成本超预期就停止，离线定位，不立刻再开收费期。一次验收失败不能称为“完美播客”，也不能成为无限追加 runner 的理由。
