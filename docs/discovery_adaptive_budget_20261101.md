# 主动取材按任务规模分配额度，并按真实缺口分批扩展

> 后续说明：[进展驱动预算](discovery_progress_driven_20261101.md)已替代本记录中的5+3固定分配；下文保留上一版开发记录。

用户要求改善通用取材能力，指出12个网页尝试不足以覆盖市场与动态自选股。本轮改默认 `discover()`，不人工补任何一期内容，不接入或恢复scheduler，不改旧失败marker。

## 分配方式

新增 `discovery_budget.py`。默认根据实际App名单数量及研究范围计算 `units = len(LANES) + len(stocks)`；当前范围7项，股票按原有名单校验去重规则处理，重复配置仍报错。

| 资源 | 首批分配（再受配置硬上限约束） | 新默认硬上限 |
| --- | --- | --- |
| 搜索尝试 | max(8, units) | 24次 |
| 新URL读取尝试，含失败 | max(16, units × 2) | 64个 |
| 额外本地补读 | max(24,000, units × 4,000)字符 | 96,000字符 |
| 单次模型输入 | max(80,000, units × 8,000 + 20,000)字符 | 160,000字符 |
| 整轮取材时长 | max(360, units × 30)秒 | 900秒 |
| 一次模型回复的工具项 | min(12, max(6, units)) | 当期不再扩展 |
| 模型输出 | min(6,000, max(3,000, units × 300))tokens | 当期不再扩展 |

默认整期模型上限仍8次，预留后续报告3次，取材最多5次，其中最后一回复须结束。取材最多 `min(8, 整期上限 - 报告预留)` 次；不足3次则在调用前报错。预留不是提前执行或消费3次，也不保证每一种复杂报告路径都能在3次内完成：既有报告可能需要更多轮取材/审查，仍受整期上限约束，不自动追加或重写。

首次正文仍返回最多4,000字符，补读共享额外字符预算；完整正文继续保存在私有工作集。模型次数有限时，可在同次回复并行列出更多不同工具请求，但执行器仍逐项执行、计数、检查截止；同一回复不能读尚未返回的新搜索候选。

## 扩展方式

不新增“批准预算”的模型调用。模型在本来就要给出的 `tools` JSON中附加：

```json
{
  "action": "tools",
  "budget_extension": {
    "task_ids": ["lane:industry:locate_body"],
    "reason": "重要行业变化尚缺原始正文，已有新候选，需要继续核对"
  },
  "requests": [{"tool":"search","lane":"industry","query":"具体缺口","reason":"具体问题"}]
}
```

先验证整批工具入参，再验证扩展申请：

- task_id必须属于当前真实反馈，所选缺口须与本次搜索、候选阅读或本地补读请求对应。
- 重要性由模型给出编辑理由，程序只校验实际缺口、请求关联、资料增量和额度，不冒充识别了所有重大事件。
- 与上次扩展相比须有新候选URL或新的合格正文阅读区间；单纯失败、空搜索、重复URL、消耗次数不算增量。
- 资源使用达到当前额度75%时可按批扩展：搜索+4、URL+8、本地补读+16,000字符。输入接近额度时+32,000字符，时长接近时+120秒。
- 追加搜索/URL/补读时，输入同时增加最多32,000字符；追加搜索/URL时，时长同时增加最多120秒。各项仍取与配置硬上限的较小值。
- 搜索失败路线不获得更多搜索额度；URL已到硬上限时，不再单独扩搜索。缓存仍可合法复用。
- 不增加模型轮次或输出上限，不挤占报告预留；最后一轮不执行新工具，不复活已到期任务。

每次申请写入私有 `primary-discovery.json` 的 `budget_expansions`，含理由、任务、扩展前后额度和拒绝原因。硬上限不代表会用满，剩余模型轮次、输入或时长先耗尽仍须停止并保留缺口。

同时修正“无新增资料止损”：不再把请求计数增加当作研究进展，连续两轮没有新候选、阅读区间或正文用途关联就停止。原失败URL缓存、搜索失败台账、三次读取尝试无可用正文就停止的保护继续保留。

## 配置、入口与旧试验

默认配置和 `.env.example` 新增/同步：

```dotenv
RESEARCH_WEB_SEARCH_MAX_REQUESTS=24
RESEARCH_BODY_MAX_URLS=64
RESEARCH_INPUT_MAX_CHARACTERS=160000
RESEARCH_LOCAL_READ_MAX_CHARACTERS=96000
RESEARCH_MAX_SECONDS=900
RESEARCH_REPORT_MODEL_RESERVE=3
MODEL_MAX_CALLS_PER_REPORT=8
```

已有 `.env` 若明确写了搜索4次，仍按4次执行；不覆盖用户配置。搜索仍默认关闭，配置额度不启用搜索、解除暂停或执行收费服务。公共读取可能有重定向，URL尝试数不是底层GET精确数。

`app.primary_discovery_check`从实际App名单生成同一套预算，仍无付费执行参数。另有不读App数据库的纯本地数量预览：

```bash
cd backend
python -m app.discovery_budget_check --watchlist-count 4
```

参数4只是给定规模，不代表读取了当前App名单。默认 `discover_current()` 继续读取并前后核对实际名单，未切换生产调度。

显式传入 `Limits(...)` 保持固定额度，不隐式改成可扩展预算；旧隔离试验runner的4次模型/8次搜索/10URL封套、输入hash、失败marker均保留，不能通过更改默认配置重跑旧失败试验。默认网关使用显式Limits时同样检查后续报告预留；注入模型的隔离调用方负责其独立已批准封套。

合并升级准备工具纳入新运行文件；原config等共享文件仍须真实部署基线，新增预算模块不能当作部署完成。本轮没有原始v20包或服务器配置，不能直接覆盖生产。

## 本轮真实执行与费用边界

实际执行一次 `app.discovery_budget_check --watchlist-count 4`，使用本地配置默认值：7个范围+给定4只股票，首批11次搜索、22URL、额外44,000字符、输入108,000字符、360秒；硬上限24次搜索、64URL、96,000额外字符、160,000输入字符、900秒；取材最多5次模型、后续报告预留3次。

本轮项目模型/搜索/网页/TTS请求均为0；未执行取材、报告、音频、测试、构建、lint、部署或推送。预算、回执联动和空搜索止损的回归用例已编写但未运行；这里只确认配置预览实际可执行，不证明扩展循环或新日期实网质量通过。

以后真实执行：预算计算及额度校验在本地执行，不占模型次数；扩展申请嵌入原工具回复，不单独付一次模型调用。实际取材继续使用现有analysis路由，更多轮次仍可能在封套内发生；更长输入/输出可能增加token费；Tavily搜索单独计费。当前是次数、字符、时长边界，不是精确人民币/美元上限，未根据未知服务商价格编造金额，也未提高整期模型次数上限。模型输入字符仍需与实际部署模型的上下文能力匹配。

无已启用Skill调用项目取材接口，本轮只更新仓库内部能力，不涉及Skill接口变更。
