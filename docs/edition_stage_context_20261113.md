# 按阶段组织输入，减少重复传输

用户拒绝 v30 的高额预算估算。本次先修复实际数据流中的重复输入，不以缩减新闻覆盖、删正文、隐藏失败或换低价模型代替。

| 阶段 | 发送 | 本阶段省去 |
| --- | --- | --- |
| 选题 | 当前时间、自选股、全部搜索候选 | 空正文、空评估和过程字段 |
| 证据评估/一次补查评估 | 全部候选、事件单、全部正文、读取成功/失败及原因 | 快照文件位置、完全重复的来源字段 |
| 写稿 | 事件单、评估结论、自选股检查、入选事件全部关联正文 | 完整搜索目录、读取回执、已经执行的补查指令 |
| 审稿 | 稿件、事件单、评估结论、上述原始正文及稿件引用来源 | 完整搜索目录、读取回执、已经执行的补查指令 |

重要事件及缺口清单始终保留。资料尚缺时原有阻断继续生效。保留入选事件所有关联正文，避免只发送评估已摘引的支持段落而丢掉反证；独立的自选股证据也会发送。正文不截短，时间、质量、主体、来源用途限制不删除。`metadata` 只在字段值与外层完全相等时去重。

全部候选、原始正文、回执仍在原一期的本地账本中。新增 `input_audit` 逐阶段记录数据字符数、含系统提示词的总字符数、正文字符数和来源 ID，并写入可读回执；它不代表模型理解或独立事实验证。

## 范围与验收

本次新增六条离线回归用例，尚未在本环境运行；服务器 v30 曾通过的25条结果不能充作本次31条通过。此次未运行项目测试、导入项目、调用模型/搜索/TTS、修改服务器或恢复自动化。需先在服务器隔离副本上运行离线检查，结果通过再安装。

模型请求政策仍是正常4次、有新增正文才增加一次补查评估。没有新增修稿循环、收费重试或后台补查。本次不会再买一期验收，也不承诺凭减少字段就能达到固定单期金额。

原本配置的65,000字符单次上限、累计325,000字符和保守预算公式未改，因此预检显示的极端费用预留不会因本次修改自动下降。下一次允许联网前，应基于各阶段实测输入与当前服务商价格另定用户接受的金额；目前尚未取得新的费用授权。字符减少不等于等比例 token 减少。

本包只针对已安装的 v30 两处运行时文件变更：更新 `edition_pipeline.py`、新增 `edition_context.py`。基线和其余 v30 依赖会核对，保持配置、数据库及暂停状态。实现不被已有 Skill 调用，无 Skill 接口变更。
