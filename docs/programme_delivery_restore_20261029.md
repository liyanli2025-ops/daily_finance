# 恢复原版节目方向（2026-10-29）

用户指出人工口播不像原版。已回查升级前918b366的正式播客提示词及.codebuddy历史需求。旧版核心是通勤早报快节奏、信息密集、围绕今天怎么操作；晚报复盘并准备次日；主线贯通宏观、板块、个股与应对，自然聊天但分析深入。用户后续要求上限20分钟、长度依有效信息决定，不强调20年身份、不编、不泛泛而谈。这些要求共同适用。

## 修改的实际运行路径

- 上游报告：REPORT_POLICY增加增量事实、同口径比较、具体传导及当前取舍。不能只列两面可能性或用观察替代分析；缺资料的环节收窄，不强迫买卖。生成与修稿均复用此规则。
- 消除冲突：_get_writing_philosophy不再要求每个话题逐项填全部分析字段；正式写稿去掉1500—3500字目标。支持/反方/期限/失效仍需核验，但不规定每段叙事顺序。事实、时间、来源和数值门槛保持。
- 正式口播：生成器调用新的共享spoken_prompts(report, report_date, edition)，提供完整正文，只删已知末尾来源目录。早/晚/即时/周末各自有SPOKEN_EDITION_BRIEFS；以后独立验收复用该函数，不拿另一道编辑题代替节目。
- 节目目标：早报材料充分时参考2500—3000字、10—12分钟；晚报3000—4000字、12—16分钟。没有最低字数，不强行补新闻、科普、天气、称呼或身份。最多4000字、音频仍不得超过20分钟；没有真实音频时不保证实际时长。
- 叙事：先给重要变化及决策含义，用事实、比较与机制讲透；按有依据的联系自然递进，不把“判断—反方—失效”套成循环。核验限制自然带入，不逐段讲方法和免责声明。
- 口播不能替上游编造新闻、行情、订单、资金或分析缺口；也不能把已有明确倾向都冲淡成等待。现有报告→口播核验继续执行，没有额外模型调用。
- 缓存：节目交付要求纳入已核验脚本签名；风格要求变更后旧缓存失效，避免新规则实际被老稿遮住。
