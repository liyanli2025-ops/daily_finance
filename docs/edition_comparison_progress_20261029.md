# 早晚报对照底稿修复（2026-10-29）

本批尚未部署，线上v5保持暂停；不新增模型、TTS、行情或新闻请求，不迁移App数据库。

## 实际问题与修复

- 原晚报写作拿到morning_report.content，审查和修稿没有早报原文。现在写作时冻结同一份对照文本，审查、修稿及原句锚点核对共同使用；私有review诊断的generation_context也保存此底稿，离线复核可找到原判断。
- MORNING数据库类型也保存即时更新。旧查询按最新一条可能拿到午后结果。本次当日查询只取北京时间00:00到09:00之前创建、标题不是即时更新/周末回顾的morning记录，仍按最新合格版本取值。此09:00边界沿用现有生成器将9点以后标为即时更新的口径，不是独立核实的交易日历。
- helper再次校验日期、报告类型、标题、创建时点、正文；带时区时间先转北京时间。沿用既有数据库naive时间代表北京时间的约定，无法修复历史错误写入的服务器时区。时间未知时不给早报比较。
- 不合格或缺少早报，明确没有对照依据，但不阻止晚报讨论当前市场；审查/修稿不能补编原话和命中率。
- 早报正文保留原条件、期限及正文引用，只移除已知文末来源目录。它只证明当时写过什么，不证明其中旧事实仍正确，也不是本期新增新闻证据。不把早报ID混成新闻ID；当前报道和行情仍需支持结果判断。现有请求字符上限不改变。
- 重用同一服务生成下一期时重置对照文本，防止上一次晚报的早报残留；冻结后的原文不会因外部Report对象修改而悄悄变化。

这不是预测准确率系统。未完成跨数日判断档案、触发时点及结果的自动核验、独立交易日历或连续实盘复盘；不能把仅有原话和一个收盘价当作命中。旧BacktestService关键词评分继续停用。下一步集中核对正文到口播的完整保留和真实生成表现，不能以更多程序测试代替听感或投资质量验收。无需为单项修复再让用户上传小补丁，本批纳入合并包。
