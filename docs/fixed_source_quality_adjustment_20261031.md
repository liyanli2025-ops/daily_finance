# 固定信源要修的是取材任务和内容质量，不是来源数量

## 用户已明确指出的问题

大量普通非相关个股财报挤占资料池；牧原等同一公司的同题材料重复；论坛、消费融资、宣传软稿混入；市场收评、海外大事和有实质经营变量的行业材料覆盖不足；标题、摘要、短片段被数量统计掩盖。公司无新消息可以接受，不能围着少数自选股反复凑覆盖。研究应广，节目再按重要性取舍，不用8/28等篇数目标代表质量。

既有解析器、原始时间处理、缓存与失败暂停值得复用，但不能因此宣布固定源内容已经合格。新增主动搜索也不自动解决固定采集的缺点。

## 本次查实与已改

固定源并不是同一种算法。直连媒体已经使用`news_assignment`阅读线索，研究输入也有按问题平衡；但直连首页正文队列仍是单一排序，见闻/证券时报另有自选股匹配加分及固定保留几篇的策略，海外正文又主要按列表顺序读取。有限耗时下，后面的编辑平衡无法挽救根本没机会下载的正文。

本次加入共用`news_assignment.discovery_order`，接入直连媒体、见闻/证券时报和海外三类正文请求队列：

- 在同一提供方内，先让不同已识别研究问题轮流取得读取机会，再读同方向的后续稿件；不同当前自选股分别排队。
- 不删除候选，不设置文章数量目标。原标题/既有排序只作为同问题内的次序参考。
- 完全相同标题的多入口延后读取但保留；这不是语义同事件去重，也不证明内容相同或来源独立。不同标题的新增事实/反方不按同题直接删除。
- 标题只产生读取线索，不记成正文已读，不用URL日期猜首次发布时间，不证明事件重要或预测有效。
- 不新增源/探测、不重试失败接口、不调用LLM/TTS/付费搜索、不恢复调度。不改现有原始池、后续正文检查和费用保护。

已有来源之间的轮询和每家并发保护保持。此次只平衡每个提供方的候选，不是跨所有媒体的统一语义主编，重复事件仍可能通过不同媒体占读取机会。

## 验证

56项相关离线回归通过，覆盖直连与海外读取器、见闻/证券时报、阅读分工及新增候选顺序。
新增回归包含：同一自选股20份财报线索与A/H/美股收评及政策竞争时，不让前者连续吃掉最早读取机会；换股后另一家公司不等旧公司全部读完；重复标题保留且不冒充已读；直连首页真正接入新顺序。测试全部使用本地材料或模拟，无实际媒体/模型请求。

这不是新一期采集验收，也不证明这一排序等于财经主编判断；源码尚未部署服务器。

## 仍未解决，下一步应按内容验收

1. 入口范围仍有限：首页/当前列表不能覆盖整个72小时。需要按市场时段、宏观、行业经营、重大公司事件检查真实遗漏，再决定补哪些栏目/搜索入口；不对旧失败接口重复试探。
2. 发现仍依赖标题线索；英文、无明显关键词的重要事件、动态行业代表公司关系存在识别缺口。不能继续无限增加几个词就宣布解决，应由广泛目录、实际内容和主动补查联合判断。
3. 跨媒体的同事件、增量、反证与原始来源仍需内容级研究，不因标题不同就算新事，也不因标题相同就认为没有增量。
4. 正文可读不等于有价值：下一轮用新资料检查市场主线、重大外盘与政策、行业变量、动态自选股、公司风险的事实覆盖；列出重要遗漏、重复占用、正文不足及低价值稿原因。不要以“几百条”“全是全文”宣布通过。
5. 外部通用搜索默认关闭且尚无服务器真实验收，当前对话的手工搜索不等于生产程序能力。完整新一期测试前仍须免费检查可用能力、材料范围和请求费用，保持自动任务暂停。

固定源的任务是持续发现和取得可核资料，不是决定所有节目选题；主动搜索补重要遗漏与反证；分析层判断真正变化和交易意义；节目层组织自然口播。这四件事分别验收。
