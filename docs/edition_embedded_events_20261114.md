# v36：综述多事件与已存正文复用

本轮由历史内容核对触发，处理通用采集/阅读流程，不补写某一期新闻来冒充程序能力，也不按特定候选或事件ID硬编码。

## 真实材料揭示的问题

截至2026-11-05的历史8篇写稿资料中，标题为A股收评的中金在线综述，其正文还出现美国中期选举的媒体预测。旧稿引用该文的国内政策却没提及选举，说明不能凭文章标题把正文的其他事件全部归到市场行情。该段只支持“文中转述媒体预测”，不证明选举结果已独立核实；专题候选读取失败与综述有相关段落是两件事。

代码审查发现两个可能阻碍当前统一入口的问题，不宣称它们是旧runner漏稿的已证实唯一原因：选题把candidate_ids在全部事件中强制唯一；后续新发现事件复用已存正文时，仅按text hash判断进展，即使新增了event_ids也会提前停止。

## 修正

1. 同一候选可用于多个不同事件；各事件内部候选仍不得重复，事件ID仍唯一。每个候选必须归入事件或明确排除，不能使用和排除重叠，不能漏掉或凭空增加候选，排除项也不能重复。
2. 明确评估须检查综述里的其他重大事项，不只看标题；媒体预测、已确认结果与原始发布保留区别。
3. 正文已存时不重新下载；新增一项有效事件关联可以进入原来的条件评估。进展回执单独记录新增/改变正文ID和复用正文的事件关联，不能把复用算成第二份独立来源或新增事实。
4. 关系新增仅允许进入证据核对，不直接改ready。证据、quote、用途、时效与重大缺口仍检查；若评估仍missing，停止写稿。既没有新正文也没有新关联仍停，保留patch_no_new_body。

## 验证与边界

新增7条回归，完整95条待服务器隔离执行；本地本轮没有运行项目测试，没有搜索/GET/模型/TTS。本版仍是正常4次、条件追加1次模型；用量账本、输出额度、价格、费用接受、暂停均不改。可复用初始同篇正文让两个事件正常经过4阶段；在评估时才发现新事件则最多进入已有第5次条件评估，不另建收费runner。

结构回归不能证明模型在实际新闻里一定会发现事件、判断事实正确或覆盖充分。旧稿计算错误由人工审阅指出，没有新增专门适配53.6/200的规则。尚无完整当期真实样片通过，用户未接受单期金额，不能直接解除暂停收费运行。
