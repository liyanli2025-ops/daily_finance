# 主动取材到报告输入：本轮接通范围与实际结果

本轮继续使用 `57e4f0a` 派生的任务分支，包含上一轮尚未提交的读取验收改动。所有修改仍在本地，未推送 GitHub、未部署，生产暂停状态未操作。

## 从哪里接到哪里

之前 `discover_current()` 和隔离试验 runner 仅交研究状态、工具回执和待人工验收底稿；报告生成器没有消费它们，旧 scheduler 仍调用固定源采集。

本轮增加以下显式路径：

```text
成功的主动取材 + 同期工作集
  → 名单复核后导出 report-input.json
  → 默认免费的 app.primary_report_check
  → PrimaryReportService 的显式报告生成方法
  → 既有 AIAnalyzerService 写作 + 首次独立报告审查
  → 只保存私有 report.json，等待人工验收
```

`finance-search-primary-v1` 显式资料包也能进入相同报告输入。这允许聊天辅助取材和服务器模型取材交给同一个报告接口，同时明确标注不同来源与账本能力。

本轮没有恢复 scheduler、添加公网触发接口或自动发布成品。新报告路径只生成报告草稿，不调用口播/TTS，不写 App 报告表；旧自动流程本身未切换到新路径。代码接入不等于收费成稿或线上工作流已经验收。

## 资料如何保持一致

- 模型取材导出保持原始证据 ID、实际存储的全部正文与正文 SHA256。取材模型实际收到的片段单独记 `discovery_provided_ranges`，不会因为存了全文就声称取材模型读完全文。
- 导出逐条比较工具实际返回文字和存储正文。无正文回执、文字被修改、失败或预算耗尽的取材，均不能导出成可用交接文件。
- 保留原始截止、观察时间、模型底稿、实际执行账本和上游调用数。观察时间未知就标未知；截止后取得的网页不能证明截止时已可见。
- 报告使用同一个证据工作集，完整池可检索、补读后部。取材模型的事件排序、观点与覆盖自述是待核材料，不是写作指令或事实。
- 写作与审查共同得到主动取材上下文。显式资料包的人工审阅备注、缺口和来源说明也传入；空名单只是输入名单，默认未与真实 App 核对。
- 报告阶段关闭外部新闻搜索、URL补采和论坛补采，仅允许本地检索与补读；不重新跑固定媒体扫库，也不自动重做上游收费取材。独立的行情服务仍按既有逻辑取得报价/技术数据，公开请求数未在此合并计数，须按来源时间使用，不能冒充新闻截止时点的同步行情。

## 暂停、费用和重复执行

生成方法先检查既有生产模型暂停，随后才允许读 App、取行情或建立报告工作集；没有暂停豁免或自建直连模型 transport。生产暂停时生成请求会停止，不能靠该入口做隔离收费验收，也不能为它删除暂停标记。

执行需显式 `--generate` 与免费预览的 `--input-sha`。这是会调用模型的动作，本轮没有执行。请求不设自动网络重试和自动整篇修稿；写作/补读轮次/首次独立审查都在现有整期模型请求预算内。默认总上限为配置的 8 次：例如上游取材已用 4 次，下游最多剩 4 次；额度不足直接停止，不重新获得 8 次。外部资料包的上游模型用量未知时预览保留 null，不能据此承诺端到端总费用。

同一输入使用独占开始标记，失败也不自动重跑；输入与检索截面超过 2 小时停止执行。生成期间的模型调用还检查资料到期和当前名单；数据库不可读不回退缓存名单。执行过程中即使模型已扣费但失败，也保存失败状态，不宣称成稿成功。

请求次数/字符数都不是金额上限。本轮只接入已有生产网关，后续真正的收费阶段需先明确隔离环境、阶段范围、调用上限和实际验收目标。

## 默认使用方法

在项目自己的 backend 运行环境执行：

```bash
python -m app.primary_report_check --input 本期资料包.json
```

输入可以是成功取材工作区导出的 `report-input.json`，或符合现有显式主资料契约的 JSON。默认只核对本地资料、展示来源、正文范围、名单、时点、覆盖缺口及预算，不联网、不生成报告、不读 App 数据库；因此输出 `watchlist_checked_against_app=false`。

`fresh_for_generation` 只是时窗/收据条件，并非内容或事实通过。`automation_paused` 来自当前运行目录中的维护标记，不代表另一台生产服务器；本轮本地环境没有该标记，预览 false 不表示远端已恢复自动化。

成功取材现在自动导出交接文件。旧失败 `model-led-primary-v1` 不会因此重新运行，原开始标记、试验 ID 和费用上限不变。没有成功结果时不能把旧失败结果改名为新输入。

## 本轮真实网页读取结果

在本任务隔离目录安装 Trafilatura 2.3.1 及最低运行依赖，没有改系统 Python 或生产 venv；只使用 wheel，未执行构建/编译。无参依赖检查实际返回 `import_ready`。

通过当前对话搜索工具发现新候选（不是服务器 Tavily，未用用户模型密钥），对三条具体新 URL 各发一次 GET，实际合计 **3 次公开 GET、0 次重试、0 次用户配置模型/Tavily/TTS 调用**。

| 新候选 | 初次结果 | 处理后范围及局限 |
|---|---|---|
| [A股收盘报道](https://finance.sina.com.cn/wm/2026-10-30/doc-iniwywtu2263586.shtml) | 解析出 423 字符，分钟时点 | 可读，但正文夹有投票、周边商品推广，且有不同的内嵌日期；不把它认定为合格主资料。 |
| [港股收盘报道](https://www.chinanews.com/cj/2026/10-30/10723632.shtml) | 取得网页，但缺可识别发布时间而拒绝 | 从保存页面识别显式发布时间字段；不取注释或推荐新闻日期，不猜时区。正文容器保留 496 字符，排除算法初次混入的推荐区；只保留日精度。 |
| [美股收盘报道](https://finance.sina.com.cn/stock/usstock/c/2026-10-31/doc-iniwzyfm4338275.shtml) | 解析出 1253 字符，分钟时点 | 可读；机构表述、据报和预计措辞仍须按媒体归属审阅，未独立核实。 |

港股修复只回放本次已保存响应，没有重新 GET；失败台账未解除。通用算法最初取得的港股 743 字符含推荐区，后来按明确文章容器缩为 496。不能把三项可读结果全算通用算法收益，也不能据此称任意网站都能读取。

三份正文已通过实际 `app.primary_report_check` 输入命令。仍明确显示缺少 `global_policy/commodities/industry/company_event` 方向；A/H/美股字段只是本次材料声明，不是市场覆盖充分。未读取用户 App，演示资料的空名单不代表用户没有自选股。本文仅记录读取/交接，不验证新闻数值或作投资建议。

原始响应、全文和回执保存在本任务 `backend/data/episodes/episode-*` 的私有工作集中，不加入公开源码交付；沿用原 episode 到期清理机制。输入 SHA、来源摘要和实际检查结果另有不含全文的交付摘要。
