# 取材协议、阅读字段与周末用途窗口（v25）

本轮在v24源码基础上修改通用能力，不改写某期新闻、旧模型回复或失败结果。生产自动化继续暂停。本环境只人工审阅代码、核对上传数据与打包哈希，没有执行项目代码、测试、编译、联网取材或收费服务；下述新行为待用户服务器离线验收。

## 实际证据

用户服务器已安装v24（74656dc0d4d507cf2a17b2c3d1aa7b7ea5a94ee7），80个离线用例通过。其后实际续采失败于`discovery_duplicate_json_key`：最后回复的两个事件分别重复了同值`lane`，不是冲突值。新增6次模型、1次搜索、11次网页请求；结果计数含历史段，不能当作全部新增。分页后六次输入均低于108000字符，Kitco中间3101字符已补读；三份存文进入完整返回的模型请求，但四股仍没有直接正文。失败结果不能用于报告。

本轮重新用独立标准库脚本核对上传包9份快照的字节数、SHA256和URL文件键，均匹配。原结果SHA256为`b96ea1a0285a93c16dbfdaa2042c606ce0b18f98add12878cd1e645fe9f4d3af`。这只证明输入完整，不证明新解析器通过。

## 通用修改

1. JSON只接受一个完整对象；同键的类型和完整值递归一致时去重，记录字段路径和模型轮次，不需要额外模型调用。不同值、布尔与数字混淆、截断、多对象、非有限数字仍拒绝。事件范围非法单独返回`event_lane_invalid`及合法枚举，不再误报四项研究检查缺失。
2. 识别文章内移动端h2标题、发布头部英文日期、`data-showtime`、明确的文章epoch秒字段。优先保留已有强适配器及显式元数据，不从URL/搜索日期/推荐区猜日期；无时区保留日精度和边界检查。标题缺失与正文不足分开报错。其他显式日期字段保留为待核对口径，不擅自消除文章日期矛盾。
3. 公司直接资料核对标题或明确的公司开头主体。仅文中同行比较不计为该股直接材料，可换为行业用途复用已存正文，不增加URL请求。明确“本文基于AI生产”的稿件排除，保留原快照供找原披露；提及AI产业本身不排除。
4. 有200响应快照的结构、日期、窗口或内容准入失败，记为`needs_local_review`并缓存，不把它写成网站访问失败，不自动重请求。401/403/超时等访问失败仍遵守停用台账；已有旧停用记录不删除。

## 时窗贯穿整个链路

新任务保存版本化`time_policy`；每份成功阅读回执记录`source_window`。搜索、正文读取、资格反馈、本地补读和报告导出/再导入使用同一口径。导入端校验用途、原截止和规范小时数，不接受任意扩大后的小时值。没有新字段的历史任务保留原72小时规则，不能安装后悄悄把旧失败材料变为合格。

| 用途 | 平日 | 周末 |
| --- | --- | --- |
| 普通发现、最近完成收盘 | 72小时 | 96小时 |
| 公司事件、已发布政策资料 | 72小时 | 168小时 |
| 评论、行业对照与反证背景 | 168小时 | 168小时 |

周末仅根据原截止的星期判断，不是交易所日历。行情仍须核最近已完成交易日及盘前/盘中/月度等口径；较早公司稿与政策可作背景，不能冒充当天新消息。评论用途或超出市场窗口的背景不计为最新行情/政策底图覆盖。报告的新鲜度2小时、App名单、证据哈希、研究缺口、独立预算和生产维护暂停均保留。

`read.purpose`可显式指定，与search同枚举；省略时direct按company_event、industry/counter按commentary，market参考其实际检索用途。只是资格与用途，不认证事实或来源独立性。
