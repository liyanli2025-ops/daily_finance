# 分时与覆盖样本宽度（2026-10-28）

本轮代码承接选材/周级参考，尚未获服务器部署验收确认。没有模型、翻译或音频调用，不代表文案质量、投资效果已达标。

306项离线测试通过，覆盖未完成尾点、累计计数回退、金额缺失、A/H尺度、午休、身份/日期、时钟停滞/未来、部分样本不能算宽度、失败停止调度、不重试、动态自选股及正式采集/提示词接入。

## 1. 已验证的新入口

参考了维护者公开代码/兼容说明和本机已安装AKShare源码，再独立实现有界采集、逐项校验和计算，未导入整个外部项目，也未使用其重试链或私有token。

- 腾讯分时：`https://web.ifzq.gtimg.cn/appstock/app/minute/query?code={symbol}`；参考[cnstock-cli兼容说明](https://github.com/fatecannotbealtered/cnstock-cli/blob/main/docs/COMPATIBILITY.md)、[stock-sdk常量](https://github.com/chengzuopeng/stock-sdk/blob/master/src/core/constants.ts)。公开无版本契约，不是官方SLA。
- 新浪目录：`https://vip.stock.finance.sina.com.cn/quotes_service/api/json_v2.php/Market_Center.getHQNodeStockCount?node=hs_a`及同目录`Market_Center.getHQNodeData`分页；参考[AKShare配置](https://github.com/akfamily/akshare/blob/main/akshare/stock/cons.py)及本机安装的`stock_zh_a_sina.py`。目录只是样本成员来源，价格字段没有日期，不直接用于宽度。
- 腾讯逐股报价：`https://qt.gtimg.cn/q={symbols}`；在现有已用报价路径上，分批核对每只股票的代码、完整日期、现价、昨收与涨跌幅。不是由采集时间推测行情日期。

没有调用旧的东方财富宽度、同花顺技术榜单、两个暂停ETF日线或其他失败旧端点。GitHub曾尝试的AKShare main分支旧文件地址404，不重复读取该旧路径；用本机已安装源文件和实际返回结构核验。

## 2. 分时能力和边界

`intraday_context.py`默认覆盖上证指数、恒指及App当前动态A/H自选股；不是固定三只股票，也不是扫描全市场每股分钟线。

已实际读取上证、恒指、一只A股和一只港股样本，四个响应各109个时点。在相应源报价时钟下，排除尾部当前/未来标记的2点，留下107个确认过去的观测点；保存页面后仅离线重放，没有反复请求。

- 分时记录是价格点及累计成交计数，不是完整的一分钟开高低收。只计算相对昨收、相对首个观测点、距采样峰值和采样振幅，不制造分钟蜡烛形态。
- 累计量先差分，最近5个连续观测间隔量速与前5个对比；缺点、午休跳跃、计数回退不计算。它不是较昨天同分钟放量，也不是历史量比。
- 仅股票/ETF语义适用时核对累计量/金额。实际A股样本与100股尺度一致，港股样本与1股尺度一致；需至少10个点在当日报价高低范围内且唯一尺度一致，才能给累计均价参考。不统一假设港股每手100股；无金额或不一致就留空，不称官方VWAP。
- 指数成交量单位未核实，不给指数量速/VWAP。A/H时钟分别列示，分时未复权，不与前复权日线跨除权直接拼接。
- 同日但时钟停滞、未来源时间、前一会话只剩不完整上午记录，不能靠重新抓取就包装成有效当前数据。午休和收盘采用保守常规时段规则，半日市/完整交易日历仍未独立实现。

## 3. 宽度真实验证

2026-10-28 11:31北京时间这一批：

| 项目 | 结果 |
|---|---:|
| 新浪hs_a目录成员 | 5575 |
| 取得腾讯逐股完整日期报价 | 5575 |
| 可比有效交易样本 | 5569 |
| 可比样本/目录成员 | 99.8924% |
| 报价日期 | 全部为2026-10-28 |
| 可比报价时钟跨度 | 93秒 |
| 样本上涨 / 下跌 / 平盘 | 4497 / 916 / 156 |
| 无有效交易、旧日期或旧时钟等排除 | 6 |

以上是该次观测，不是现在实时数值或买卖建议。目录成员不是独立核对的交易所上市全集；因此输出称“沪深京股票覆盖样本”，不冒充官方全A股统计。也不能把指数成分或ETF代理当这个全集。

目录要求计数、分页去重后的代码数量及结束时计数一致。先确认首分页再两并发，有失败停止新增调度，不在失效接口上循环换参数。目录缓存6小时，逐股报价缓存90秒；原始缓存延续24小时清理机制。宽度只在可比样本≥95%、时钟跨度≤180秒且源时钟有效时输出；未完成整目录或部分页不能算市场宽度。

无成交、旧日期或过旧时钟的报价不计作平盘，也不据此断言停牌。仅给涨/跌/平、等权收益中位数及±2%分布；不输出涨跌停、MA20上方占比、市场资金流。港股宽度仍缺。

## 4. 接入和验收

- `microstructure.py`并行取得分时与宽度，保存`data/radar/microstructure.json`；`news_collector.py`正式采集已接入。
- `technical_radar.prompt`读取近期有效快照，列出时点、缺口和单位限制。A股指数与宽度同日期且相差≤5分钟才标为可作附近时点比较，仍非严格同步或事件因果。独立快照超过10分钟不入模。
- `radar_check --saved-summary`可显示已保存的宽度和分时覆盖；新增`app.microstructure_check`只验收这些数据，不采新闻、不调模型/TTS，不写App数据库。
- 缓存、快照24小时到期清理由下一次任务触发；失败台账不随正文缓存清理。明确HTTP/TLS/身份/结构失败不自动重试，临时超时及未开市等有界冷却。

在服务器安装合并包后，运行：

```bash
cd /var/www/finance-daily/backend
sudo ./venv/bin/python -m app.microstructure_check
```

默认只读App当前自选股；数据库失败中止，不取旧列表。`--market-only`只测指数和目录宽度，不读App数据库。`--saved-summary`只读已保存文件，不重新请求，文件缺失也不隐式重采。冷目录验收最多110秒预算；正式采集预算40秒，冷启动未完成时宁可报缺口，不补造数量。

## 5. 剩余问题

需要在腾讯云核验网络、时钟、目录和当前App标的，然后才做少量模型文字验收。本轮不是多日分钟OHLC历史、完整分钟技术体系、港股全市场宽度、可靠交易日历或最终音频。不能把本次一次成功宣称长期稳定。

接下来重点是验证模型是否正确使用消息、日线、周级和分时/宽度的不同截止时点，形成有方向、有反方、有失效条件的判断；观察源数据缺失时是否克制，而不是继续用数据条数代替成品效果。
