# 整个采集池的质量与历史覆盖

## 本轮修改

1. 停用Finviz及五个百度RSS入口：公开验收发现它们大量返回空文本或只有标题，项目没有相应正文补全路径。状态保留为disabled，避免数字被解释成成功采集正文。
2. 合并当前RSSHub节点返回完全相同列表的华尔街见闻“股市”与“全球”入口，仅保留“全球”。这不代表两个网站栏目永久相同，恢复前需要重新验收节点响应。
3. 修正hkej入口的来源名称为信报财经新闻，保留旧数据来源别名兼容。RSS仍按采集文本/摘要使用，不因篇幅较长升级成完整原文。
4. RSS失败或无效格式设6小时冷却，显示下次重试时间；有效但有条目缺日期时显示partial，缺日期条目不猜今天。
5. 华尔街见闻公开流仅按服务端next_cursor翻页，上限4页；空页、重复页/游标和失败均停止并记录，始终不声称完整历史。原文内容合并公开的content与content_more，付费或试读仍不读取。
6. 媒体正文读取预算调整为24篇（初始分配华尔街见闻16、证券时报8，闲置名额可补另一来源），兼顾市场、当前公司及经营环节；记录候选、尝试、成功和预算未读清单，不把预算限制说成无新闻。
7. 新增私有新闻历史库，小时任务保存RSS文本与媒体/政策原文，早晚采集补回列表已挤出的旧文章。保留原始发布时间和阅读范围。只使用各地址/来源最新观察版本，历史版本用于核查；保留7天，最多15000个文本版本。补回最多3000条，截断会显示。
8. 整池验收区分本次抓取和历史补回，逐源列出窗口内条目、正文/摘要、标题、长度、过滤原因、HTTP/格式状态、同正文和同文章地址重叠。不同正文仍可能是改写转载，不提供虚假的独立事件数。

## 公众号状态

提供公开搜索与正文读取适配，默认关闭。读取公众号姓名、正文主体和原始发布时间；支持普通公开跳转的字面URL，不执行网页脚本、不处理验证码、不登录。公众号内容保持作者归属，不自动视为公司一手披露。

本地公开实测可搜到候选链接，但跳转到公众号文章后返回“参数错误”，没有通过正文验收。因此`backend/wechat_sources.json`保持`public_search_enabled=false`，不会在每期反复请求。可用的直接公开文章地址可放入`article_urls`单独验收；同样可能受访问限制，不能保证成功。失败公开搜索有6小时冷却。没有接入付费搜索或使用微信登录凭据。

## 部署后检查

先离线检查已保存采集，不重新请求新闻或模型：

```bash
cd /var/www/finance-daily/backend && sudo ./venv/bin/python -m app.evidence_check
```

旧快照仅能检查已留存池，不能还原原始去重损失和源HTTP状态。完整刷新并检查整个生产路径（零模型/零音频请求）：

```bash
cd /var/www/finance-daily/backend && sudo ./venv/bin/python -m app.radar_check --hours 72 --full-news
```

输出及私有快照包含source_inventory。历史库要从安装后开始积累；不能在刚安装时声称已经覆盖过去72小时。即使连续采样也可能漏掉两次采样间挤出列表的文章，complete_window始终为false。历史库独立于App主数据库；不修改自选股或已发布报告。

## 验收边界

2026-10-25当期研究升级调整：媒体正文不再固定24篇，改为总耗时与并发保护并披露未读候选；临时文本采样/缓存改为24小时寿命，由下一次采样或生成清理。下文及旧版本中的7天历史、24篇预算属于历史实现，当前流程以repair_roadmap.md为准。模型可按问题补读当期未预选正文，但不代表已接入全网或IMA知识库。

已完成本地公开接口实测、文本存取回读、离线链路回归和临时目录安装验证。这些不证明服务器网络、来源完整性、文章事实准确性、预测能力或口播质量。测试使用最后一次人类确认的三只股票作输入；生产代码仍从App读取动态自选股。
