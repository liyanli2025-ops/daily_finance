# 当前取材方式：由研究进展决定继续，报告独立记账

本记录替代上一版“整期8次、取材5次、报告预留3次”的默认分配。用户明确指出固定次数缺少研究充分性的验收依据，要求改通用收集和阅读能力，同时更新GitHub、在需要服务器测试时给出明确说明。

## 停止条件与预算

默认 `discover()` 的 `model_calls=null`，不再从报告8次上限分配5次取材。模型根据当前范围、实际候选、已读区间和重要事件缺口继续研究；连续无资料增量、读取路径不可用、重复结束却无进展时停止。显式传入 `Limits(...)` 的旧隔离试验仍保持原固定封套，默认不重跑。

取材保留独立、可配置的最终用量与时长边界：

```dotenv
RESEARCH_TOTAL_INPUT_CHARACTERS=2000000
RESEARCH_TOTAL_OUTPUT_TOKENS=120000
RESEARCH_MAX_SECONDS=900
# 可选紧急次数上限；不配置时没有固定模型次数上限：
# RESEARCH_MAX_MODEL_CALLS=正整数
MODEL_MAX_CALLS_PER_REPORT=8
```

累计输入按实际序列化的模型messages字符数预留，累计输出按每次请求的 `max_tokens` 保守预留，发送前检查并计数，失败也不退回这次预留。输出预留不是实际token用量，更不是金额。预算数值是本轮开发默认保护值，**未经整期覆盖质量或账单校准**，不能以预算未用完或已用完判断资料是否充分。实际token仍由现有私有usage账本记录。

搜索、URL、额外补读、单次输入、时间继续按研究范围和App实际名单规模分配，默认硬上限仍为24次搜索、64URL、96,000额外补读字符、160,000单次输入字符、900秒。可以在同一次工具回复附实际task_id与理由申请分批扩展；费用审批不单独调用模型。

旧 `RESEARCH_REPORT_MODEL_RESERVE` 仅保留配置兼容，不参与计算；旧.env显式较低的搜索上限继续生效。若配置 `RESEARCH_MAX_MODEL_CALLS`，同样如实执行，不隐式忽略用户边界。

达到任何硬边界时保留 `incomplete` 与停止原因，不能表示研究已完成。最后一次允许回复会提示结束；输入或时间不足以再发送时直接保留检查点，不额外付费让模型解释失败。

## 研究结束检查

默认进展驱动模式的每个重要event增加 `lane`、可选公司 `scope`、四项 `research_checks`：

- `primary_facts`：原始事实、时点、说法归属及新增内容。
- `background`：理解事件所需背景、可比口径。
- `disagreements`：回应、竞争解释、反证或未确认部分。
- `transmission`：影响对象、传导依据及边界。

每项必须给出 `supported / unresolved / not_applicable`、证据ID和解释。supported只能引用该event已引用的正文证据；原始事实不能标不适用。未解决项变成反馈中的后续任务，供模型选择继续搜索或补读。不同解释允许未决，不要求强行得到唯一结论。

`collection_completion` 提供实际范围缺口、所选正文未读区间、未解决/暂缓任务、研究检查问题和实际用量；没有合法结束底稿也仍明确标未完成。已提供正文只是机械准入，模型的四项判断不等于事实认证，也不能证明全网没有遗漏。当前完整度判断较严格：没有直接正文的范围、被明确暂缓的任务仍算未完成，不能因为解释了原因就改成已覆盖。

## 报告独立预算与兼容

新取材输入使用 `budget_contract=separate_collection_report_v1`。报告输入预览重新计算完成度，不盲信保存JSON里声称的完成状态；新合同未完成时，在收费报告生成前停止。报告预算独立，默认8次，不再用取材已调用次数预扣。它不承诺实际一定使用8次，也不包含音频生成。

旧合同/旧资料输入继续按既有共享预算检查，不让历史失败试验因本轮更新获得新额度。原App名单前后核对、维护暂停、模型零重试、来源失败台账、禁止自动重写/发布、试验marker继续保留。新流程尚未接入scheduler。

`collection_usage_scope` 仅隔离计费账本和输入检查，不解除维护暂停，不改变账户、路由或重试策略。取材单次输入检查与实际模型网关统一采用序列化messages口径，修正上一版规划160,000字符却仍受网关固定100,000字符限制的问题。其他旧调用默认仍为100,000字符保护；部署模型的上下文能力仍须服务器核实，配置容量不代表模型必然支持。

## 验收与服务器接手

本轮只实际运行给定4只股票规模的免费本地预算预览：7个范围、首批11搜索/22URL，`model_request_cap=null`，报告预算独立8次。没有读取实际App名单，没有调用项目模型、收费搜索、取材网页或TTS，没有执行测试、构建或lint。

新增/更新了超过5轮仍有新资料时继续、累计用量发送前停止、独立报告预算、事件研究缺口、账本scope和输入限制等回归用例，**尚未运行**。新日期实网覆盖、真实模型选择与实际费用仍需服务器验收，不能宣称能力已通过。

服务器先按 [免费验收步骤](server_collection_acceptance_20261101.md) 在隔离检出副本运行，回传结果后再制定一次真实取材的明确执行方案。旧4次模型试验runner不能验收新的默认模式，不删除其失败marker、不解除生产暂停来试新代码。

本轮仓库内部接口没有已启用Skill依赖，无Skill接口同步需求。
