# 从候选过滤转到资料来源验证

v40的实际新增请求：6次Tavily搜索、12次网页HTTP（含2次重定向）、10个URL尝试、0篇合格新正文、0次新模型。6次搜索中4次是自选股公告查询，但实际仅返回1、5、1、1条结果，含垃圾标题、公司目录、行情页和超期公告。选举中文查询返回3篇主题不相符文章。商品补搜10条候选，却被旧显式补读同缺口排重挡住；v41修复排重并在元数据过滤6个不当选择，但没有证明任何替代稿能读通。

根本遗漏之一：项目已有watchlist_sources.fetch_company_announcements按股票代码查询公告列表、核对公开时间并读正文，新EditionPipeline没有接入，仍花搜索额度找公司公告。本轮先验证这个既有公共镜像通道，不再让用户安装v41后重复整期收费试验。

本轮对现有公告适配器只增加可注入传输、条数/页数/共同截止限制，默认仍3份公告、每份5页、35秒，保留原调用行为。独立诊断使用1份/2页上限，按原期4只自选股和原截止验证，不查其他证券；最多12次公开HTTP、90秒，不自动重试、不跟随重定向、每响应最多2MiB。公告列表先核代码、显示时间及窗口，再取正文，正文编号与分页必须匹配。非本公司、旧/未来、超2页或重复分页不充合格完整正文。纯公告通道不覆盖公司全部新闻，首20条列表也不代表完整全库。

诊断不调用Tavily/模型/语音，不新建一期，不续接原付费任务，不改变原预算/费用/截止/标记，不写App，不安装或重启生产源码。记录独立公开HTTP回执、原始JSON及正文；运行前确认维护暂停和App当前自选股。已经完成直接返回原结果，已开始但中断则拒绝自动再试。请求数与原期付费账本分开展示，不把诊断请求冒充零HTTP或已入原期正文。

提供10条离线回归，覆盖公司/日期身份、公开时间与文件日区分、只读一份/两页、超页拒收、正文号错配/重复分页、非法ID、参数边界、固定URL、请求预算和重定向/防重复。本轮未运行测试或新联网请求；服务器run_server.sh先在禁网条件执行10条，再做一次有限公开诊断。失败就停，不生成安装包或假称真实通道已通过。

当前成果是可复核的通道验证工具，尚未把公告来源接入EditionPipeline。只有服务器回执确认可用后才连接同一个正文池和预算计数；若镜像不可访问，回执用于决定是否改用交易所/巨潮原披露通道，不继续放大搜索/模型轮次。国际事件的查询语言与来源选择仍待解决，不声称本轮已经解决。
